# OfficeFlow v4 工程决策与复用边界

来源：OfficeFlow 独立合成采购流程；Contract `10352140f56ddbaa61a6b1b911657909b1519418aced1cfac1ca4476c78cfd28`，run `office-efdb85f5-73fd-4f04-9175-dbc3e7db3fb4`。

模型提案、用户批准和执行权限分开。模型只提字段，不能生成URL、选择器或执行代码；正常提案仍必须经有限字段和完整词法校验。一个请求只接受一个明确数量，含范围、限定词、其他数字或取消意图要求改写。小样本规则与模型都通过，不能据此宣称模型改善准确率；模型会增加延迟，因此保留诚实来源和规则降级。

计划改版是授权变化。修订绑定旧revision/hash做CAS，新版保留需求编号、稳定业务键，保存字段差异并清掉旧批准。目标版本重新读取；执行中、UNKNOWN或已产生效果的运行不可修订。取消编辑不会改变现有批准，保存修订不会自动批准或登记。

执行先认领再启动浏览器，写入端再次检查短期capability、批准、运行epoch、参数和目标版本。业务唯一键不是所有外部系统的exactly-once保证。数据库事务将登记、效果和目标版本一起更新，D1 SQL使用实际事务时间；SQLite SQL模拟测试不替代真实D1验收。

四层事实分别保存：版本批准、浏览器DOM/字段/POST/页面回执观察、持久写入效果、fresh API全字段验收。浏览器看到POST不代表写入；丢失页面回执不等于业务失败。已有登记去重如果没有本次浏览器动作，必须明确无动作证据。报告仅白名单字段，digest只是内容校验，不能冒充签名或不可篡改证据。

取消检查是旧absence与真实commit的竞态窗口。最后CAS必须检查live效果并再次查询；当前查询失败时保留applied并标UNKNOWN。晚到浏览器异常不能抹除已发生效果。UNKNOWN恢复只查询原键，即使尚未找到也不重发；真实进程强杀与恢复必须证明新浏览器及新POST都为零。

会话隔离也包含客户端缓存。HttpOnly签名cookie被另一个标签轮转后，旧Context标记必须在服务端拒绝。前端清空记录、编辑、证明、动作状态，并使用session generation丢弃旧回包；仅修改cookie不够。

最低Node22.16来自实际SQLite backup API。独立审查用真实22.13复现启动失败，修正版本声明后用真实22.16验证64例；不能用机器Node24通过来掩盖最低版本错误。

预览与生产D1/Worker/secret分开。应用预算是本库的限额，不是Cloudflare账户剩余额度；账户免费条件未证实则浏览器和AI保持关闭。Git Integration、实际commit、HTTPS、云浏览器/DB/API业务回读是独立发布门禁。既有客户经历、本地合成证据与生产成果分别陈述。

独立审查保留所有BLOCK与输入哈希，修补后重新核验，不改provider身份或把旧QA当当前通过。默认GPT-6.1 Sol ultra的真实子代理身份和未提供的requestId边界都保留在审查收据。
