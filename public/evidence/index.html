产品定位与 PRD 证据摘要 · 2026-10-12

OfficeFlow 把采购口语和带来源的材料整理为可人工核对的字段，再把确认后的采购需求交给受批准约束的登记流程；外贸材料输出来源值、差异与待核对问题。当前使用合成数据和隔离工作区，没有真实客户交付、采购履约或节省工时的验收数据。

已确认本人主控、项目已上线；具体编码、审查、排障与 AI 协作分工按模块证据说明。PRD 原始文档保留在本机，公开脱敏版沿用上方入口；本节补充来源版本、关键机制与验收范围。查看来源版本、SHA-256 与范围矩阵。来源哈希用于匹配文档字节，不是签名或身份认证。

口语 / 文本 / 已有 OCR / VTT→来源字段 → 人工核对→未批准草稿 → 预览 / 批准 / 执行→持久效果 → 新鲜 API 核对
关键机制行为与证据边界
来源与字段文本、VTT 时间段及 OCR 分析结果的页码 / 区域形成候选。原值、人工确认值与修正理由分别保存；缺项、多值和差异不能自动变为正确结论。
人工核对与执行批准资料确认只决定字段。采购仅创建未批准草稿，随后仍需单独预览、批准和明确执行；外贸核对不触发登记、付款或履约。
版本与写入批准绑定当前计划版本、内容哈希、后台目标、适配器与期限；修订清旧批准。执行先持久认领，事务写入仍校验现场状态与业务唯一键。
未知结果恢复浏览器观察、后台 applied 效果与本次 API 核对分开。提交后断线只查询原编号，不能自动重发；取消保留已经发生的登记。
识别与消费本仓库解析提供的 VTT 并消费严格 OCR JSON；样例标记 fixture。没有运行真实 OCR / ASR provider。通用 PDF / 图片解析核心目前是设计文档，不能据此报告识别率或接入完成。
节点与操作人校验通用解析核心提出每节点收据、操作人快照与审计链的 SHA-256 设计，尚未实装到 OfficeFlow。现有计划 / 报告校验值不证明操作人身份、授权或存储不可篡改。

线上故障：安全检查阻止了 Cloudflare 错误页

第一次云端执行停止于 NETWORK_DENIED，未观察到 POST，API 没有找到登记。进一步定位到 /cdn-cgi/styles/main.css；Worker 的同域请求返回522，而外部请求到达应用。添加 global_fetch_strictly_public 后，等待版本传播，再次探测返回应用自身的 CAPABILITY_INVALID 403。临时诊断代码已移除，表单、字段与跳转守卫没有放宽。

修复后真实云端浏览器耗时3.432秒，DOM、POST字段和登记回执均匹配；D1为applied，随后独立API的九项字段核对全部通过。查看完整分层报告。原始失败记录保留在私有发布日志中。

体验范围与额度

仅合成采购需求；模型当前关闭，计划来源标记为有界规则。每个环境每天最多6次浏览器启动，间隔30秒，单次执行截止25秒。生产和预览使用独立D1。账户为Free套餐，平台共享额度和统计延迟仍可能使执行停止；结果不确定时只查询原需求。
