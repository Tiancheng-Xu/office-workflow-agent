# 自然语言采购入参整理

用户反馈：`前台买一台打印机` 不应因为没有按固定句式、使用中文数字、缺少系统编号就得到一段通用拒绝。用户应描述需求，由应用提取并编排工作流入参。

1. 单条和批量入口共享字段提取器。自由语序、常见部门/品类别名、中文整数数量及“数量：1”字段形式均可整理为 requestId/department/item/quantity。显示具体缺项或冲突，保留原话与已识别值。
2. 缺少编号由浏览器生成稳定的新REQ编号；相同页面输入重复整理保持编号。已经给出但不合法/冲突的编号必须由用户纠正，不能当作缺失自动替换。
3. 无明确部门、品类或唯一数量时不创建提案、不批准、不执行。补全控件供用户显式选择字段；不擅自把“前台”映射成行政部、把不支持物品改成显示器。危险/否定/付款/权限/链接输入不能通过补全绕开。
4. 完整字段序列化为后端已有的提案文本；后端也支持相同自由语序、中文数量和别名，继续强制验证参数与输入对应。机器编号生成仅在准备入口；直接API调用仍提供唯一编号。
5. 前台和打印机是新增受支持的合成字段，提案、运行时校验、真实表单选项、浏览器DOM校验、分层报告、交接包、模板和筛选使用同一目录定义。原部门/品类、旧记录及效果幂等行为兼容，无数据迁移。
6. 批量每行仍是一条需求，最多十条；无编号时各行分别生成稳定编号，重复显式编号继续整条阻止；只创建未批准草稿。晚到响应、会话切换、目标刷新、批准过期和报告读取互斥维持原规则。
7. 原十条只读全流程历史不覆盖、不重放。生产验收使用用户原句，实际逐条人工确认，真实云端浏览器登记，独立API九字段核对。缺项和危险输入不能写入，不能把规则提取写成模型推理。

实现范围：有限采购目录内的可解释字段提取、归一、补全和参数转换；没有引入付费模型、任意网页执行、多品类自动拆单、真实客户操作。模型提案来源继续如实展示。后续目录扩展集中修改catalog并相应验证业务范围。
