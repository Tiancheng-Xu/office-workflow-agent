# 办公流程 Agent 需求

业务：同一客户采购需求分散在语言描述和旧网页表单里；只用API不够，只让模型点按钮又不可验收。选择合成采购登记，不涉及支付/退款。

- 输入格式允许中文自然语言（例：为研发部登记12台显示器，需求编号REQ-2026-001）。数量1–100，部门为研发部/运营部/行政部，品类为显示器/键盘/办公椅。不能接受任意URL、JS、CSS selector或账户字段。
- 结构化有限计划只提出字段，不赋予执行权限。缺项/含不支持操作时请求改写，不猜测。模型超时或不可用明确显示有界规则提案及真实来源，不冒充LLM。
- 身份由受信会话建立，每个公开体验独立合成租户；不以请求体tenant指定身份。无真实员工/客户账号数据。
- API读取部门与需求编号，计划绑定目标版本/adapter版本/内容hash。预览完整目标、数量、步骤及不可逆效果。人工确认后才执行。
- 浏览器使用全新上下文及短期执行capability，不复用用户浏览器。允许同源固定旧后台页及表单POST；域名/path/redirect/popup逐层受控。DOM找不到/重复/结构变更停止，不能猜定位。提交端重复检查计划版本、批准与目标版本。
- 稳定租户+需求编号唯一键；同key同payload查询返回已有，改参数冲突。提交前认领、提交后断线UNKNOWN只核原key；NOT_FOUND仍不自动重新写，需证据和新明确确认。取消不等于撤销已发生效果。
- 持久记录执行/审批/核对/故障/耗时/版本；API独立核对实际结果。导出报告去掉token/cookie/PII。
- 正常、拒绝、重复、DOM漂移、跨域跳转、迟到、取消、并发、进程崩溃及恢复、迁移、备份恢复、负载必须实际测试。
- 生产完成须真实浏览器动作+后台结果+API核对；静态Evidence和本地预览均不计生产完成。
- FDE讲解按客户问题→约束/接口→验收→失败→迭代；用户陈述两年以上客户迭代与这个新项目证据分层。

新增深入验收：同运行计划修订（需求编号不变），字段diff、版本+1、清旧批准，执行/未知/取消/已验收不允许改。浏览器POST观察、后台已写与API核对分别留证；公开报告白名单与digest不声称密码学签名。恢复面板明确最后确认点和仅核对允许动作。
