# 采购运营工作流增强

目的：从单条演示扩展到多部门需求准备、逐条审核、异常分流和核对交接。保留原工作台与十条不同终点的历史证明。授权沿用用户的自主实施和生产发布指令。

## 验收接口

测试通过网页、现有 /api/propose、/api/runs 与 /report 公共接口观察结果；不以内部对象或数据库旁路证明成功。

1. **批量准备**：一次粘贴 1–10 条合成需求，每条独立一行。逐行使用与服务端相同的有界规则识别完整字段；标明缺项、歧义、输入中重复编号和当前工作区已有编号。任一重复编号的所有行都阻止创建，即使其中一行字段无效。超过上限整个输入拒绝，不截断。预检仅本地抽取和读取当前会话，无浏览器/提案/审批/业务写入。提供结构化部门、品类、数量、编号输入来追加一行；每条生成前均展示完整字段。
2. **草稿生成**：用户点击后先刷新当前工作区，再按顺序为通过预检的行调用现有提案 API。每次只创建一个未批准草稿；绝不批量批准、执行、取消或修订。成功行显示真实运行链接。遇到失败立即暂停剩余行；连接/超时/非可靠响应标为结果待确认，只能先读取已有草稿，不能自动重发。读取到相同编号且业务字段一致可链接已有运行；不一致阻止。刷新网页清空临时输入，但服务端草稿仍在当前会话记录。会话切换清空临时输入、链接与异步结果；并发点击、单条提案与批量提案互斥。
3. **运营队列**：当前会话已读取的服务端记录（单次读取最多100条）可按编号、部门、品类及错误码搜索，按部门及待审核、待执行、需核对、已停止、已完成分类筛选。有不确定/已发生效果的非完成运行优先归需核对；已完成运行尚未读取报告、报告读取失败或本次查询未确认，也归需核对；交接包读取结果同步队列，保留历史状态和效果；批准过期归待审核并明确需要重新确认（刷新目标并重新预览入口）。所有记录的批准过期后自动重新分类，无需先选中或手动刷新。筛选不修改实际状态和业务概况，也不混入只读历史。行展示实际状态、错误码和下一步建议；点击仍到原逐条审批/执行/恢复面板。
4. **核对交接包**：为当前筛选结果最多十条，逐条 GET 原报告，导出 JSON。明确导出时范围与各报告 checkedAt；成功、读取失败分别保留，不能把运行状态 verified 当作本次 API 验收。报告经过白名单结构及敏感键清理，无 CSRF/cookie/capability/租户信息。下载只读、不会登记；筛选快照固定，会话切换停止并禁止旧包下载。报告部分失败仍可导出并明确标为不完整。

## 方案与边界

复用现有 planner 的确定性抽取、服务端租户隔离/CAS/审批/唯一键、逐条核对报告；新增前端 intake 和 operations 模块，无新数据库表、云资源、模型调用或解析引擎。临时准备不是持久批次调度器；刷新后通过服务端记录继续审核。不同标签页同时提案仍可能产生同编号多个草稿，界面重复检测是准备辅助，最终业务唯一键由服务端执行保护。未知写入绝不自动重试。

实现顺序：批量预检红绿测试 → 顺序草稿与中断恢复 → 筛选队列 → GET 报告交接包 → 会话隔离/手机验证 → 双轴独立审查 → CI/Pages预览 → 合并生产回读。保留新的真实 QA 输出，原十条发布历史不覆盖。
